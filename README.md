# headphone-lab · 头戴式耳机实测分析引擎

> 目标：**用 1000+ 条实测频响取代主观转述**，把"推荐/分析"建立在可复算的数据上。
> 状态：v1.0 · 2026-10-11

---

## 1. 为什么要重建

旧版技能用 7 条 0–5 的主观轴值（评测定性转述，conf 0.4）——扩库到 34 只后出现 **19 只同分并列**。
证明瓶颈不是"型号太少"，而是**分辨率 + 数据不实**。本项目把这两件事一起换掉。

**不默认开启**：白名单是主观的「常见」判断，不是测量结论。
```bash
python src/engine.py --mainstream --top 10    # Sony MDR-7506、X2HR、Z1R、SRH1540…
```

## 3. 特征层 `src/fr_features.py` → `data/features.json`

1. 统一网格：**1/12 倍频程，20 Hz–20 kHz，121 点**（跨来源可比）。
2. 每条曲线**自身归一化**（300–3 kHz 均值 = 0），消除绝对电平差。
3. **数据驱动参考基线** = 全体曲线在该网格上的**中位数**（不编造 target；基线由数据集自定义，可审计）。
4. 偏差 `dev(f) = 曲线 − 基线`，全部特征由 dev 派生：

| 特征 | 定义 | 用途 |
| --- | --- | --- |
| `sub_bass / bass / low_mid / mid / presence / treble / air` | 各频段 dev 均值 | 音色骨架 |
| `tilt_1k_10k` | 1–10 kHz dev 对 log2(f) 的回归斜率 (dB/oct) | 亮/暗 |
| `peak_5_10k_db / _hz` | 5–10 kHz 最大正偏差及频率 | **齿音/疲劳** |
| `sub_extension_db` | 20–40 Hz 相对 60–200 Hz | 下潜 |
| `roughness` | dev 一阶差分绝对均值 | 粗糙/共振 |

## 4. 匹配层 `src/engine.py`

- **目标曲线**：给了「喜欢」锚点 → 目标 = 锚点均值形状 + delta（用你的耳朵定基线）；否则人群基线 + delta。
- **感知加权**：频段重要性 ×（有锚点时）**判别权重**——喜欢与讨厌样本差异越大处权重越高。
- **不对称峰惩罚**：`max(0, d−2)²` + 5–10 kHz 峰护栏（"别刺"）。
- **跨来源一致性 = 置信度**：同型号多来源曲线的平均离散度；≤1.5 dB 记"一致"，否则"分歧"。

用法：
```bash
python src/engine.py --bass 3 --presence 2 --treble 1.5 --peak-guard 5 --top 20
python src/engine.py --like "HD 600" --like "HD 650" --dislike "Edition XS" --explain "Edition XS"
```

## 4.35 可闻性判据：把「差几个 dB」翻成「听不听得出」（`src/audibility.py`）

引擎的 `score = 100 − 7·rms − 6·peak` 里，系数是手调的、**不对应任何可验证量**。
本模块并排给出一个**有出处、可核对**的判据：**哪些频段越过了文献里的阈值**。

### 文献依据（含可信度分级）

| # | 结论 | 出处 | 可信度 |
|---|---|---|---|
| 1 | 训练听音者双盲下需 **≥6 dB** 频谱偏差（集中 **1–4kHz**）才能做出统计显著的偏好区分 | Olive & Welti, AES 2013 | ⚠️ **二手转述**（AES 原文付费墙，本机取不到） |
| 2 | 偏好评分 **82%** 方差由频响**平滑度**解释（1/12 倍频程移动平均 RMS）；「单元类型」解释 **<1%** | JAES 2022 | 二手，但口径与本项目 1/12 倍频程网格**恰好一致** |
| 3 | 相对 Harman 的 RMS 误差范围 **2.5–13 dB**（283 款） | Olive 分析 | 二手 |
| 4 | **100–1600 Hz** 不规则性影响**前后方位判别** | ICA 研究 | 二手。频响不只改音色，也改「声音在脑内何处出现」。**已在 §4.36 建模**；该条本轮未取到原文，故登记为"不作判据" |
| 5 | 零售价格与实测频响**无相关性** | Olive 分析 | 二手 |

**所有阈值都按频段分别给**（文献支持「偏差落在哪段」比「多大」更要紧）。
`band_threshold()` 对文献没覆盖的频段（500Hz、6kHz、12kHz…）**返回 None**——
把 1–4kHz 的 6 dB 平移到别的频段是伪造依据，`tests/test_audibility.py`
有一条断言专门挡这个。

### 两个必须分开的概念

    LEVEL_JND_DB      = 1.0    宽带**电平**变化：人耳极敏感
    PREFERENCE_JND_DB = 6.0    有限频段**形状**偏差：要 6 dB 量级才改偏好

机制不同，混为一谈是这个领域最常见的错误。

### 全库普查实测（`python src/audibility_survey.py`，849 个型号）

| 频段 | 分布 | 越阈比例 |
|---|---|---|
| 1–4kHz（相对目标，阈值 6 dB） | 中位 −3.97 ｜ 5% −11.56 ｜ 95% +5.99 | **280/849 = 33.0%** |
| <200Hz（阈值 3 dB，**工程估计**） | 中位 7.13 ｜ 最大 46.55 | 811/849 = **95.5%** |

**两个结论**：

1. **6 dB 判据有区分力**（33% vs 67%，两个方向都有人）。
   越阈名单正是该越阈的那批：RUNMUS RGB K1、Redragon Diomedes H386、
   JBL Quantum 400、Cowin E7 这类游戏耳麦与低端消费型号，
   以及 DubsLabs Bedphones（−22.4 dB @3991Hz）。
2. **我那个 3 dB 低频阈值没有区分力**——95.5% 都在同一侧。
   因为它是**我拍的，不是文献给的**。普查脚本会自己把这条诊断打出来。
   它的用途仅限分级参考，**不可当判据引用**。

### 对候选集的直接影响

默认参数下前 12 名的 1–4kHz 最差偏差只有 **1.8–4.3 dB，一个都没越过 6 dB**：

    Dan Clark EXPANSE +1.8 @2992Hz ｜ Oppo PM3 +2.1 @2667Hz ｜ Focal Hadenys +3.2 @3557Hz
    HD 280 Pro −4.3 @3991Hz ｜ E3 +2.7 @2825Hz ｜ HD 490 Pro −3.9 @1783Hz

即按文献自己的判据，**这批耳机在关键频段上是听不出差别的**。
这比 `stats.py` 的「CI 区间重叠」更强——后者说「统计上不可区分」，
前者说「**感知上**不可区分」。

**这不代表它们听起来一样**：1–4kHz 之外、以及本模块不覆盖的维度
（声场、瞬态、失真、佩戴）仍然可以差很多。

## 4.36 空间维度（`src/spatial.py`）——把"查了却没用上"的欠账落地

上一条文献里第 4 条（100–1600 Hz 影响前后方位判别）此前**只记在注释里**。
本模块把这一维做出来，同时把"算不了"的边界一起写清楚。

### 先纠正一个流传很广的说法

耳机重放时，耳机自身的频响偏差 H(f) 是**同时**加在左右两耳上的同一个滤波器：

    ILD_out(f) = 20·log10(|X_L·H| / |X_R·H|) = 20·log10(|X_L| / |X_R|) = ILD_in(f)

**ILD 完全不变，ITD 同理。**所以"这只耳机频响不平整 → 声场歪了"这句话在物理上
是**错的**（`tests/test_spatial.py` 第一条断言就钉这个）。FR 能影响空间感只有两条路：

| 路径 | 机制 | 本库能不能算 |
| --- | --- | --- |
| **左右单元不一致**（H_L ≠ H_R） | 真的改写 ILD/ITD → 结像偏移、声源宽度变化 | **需要逐声道曲线**——只有 squig 那批有 L/R 分文件；AutoEq 是单条。没有时返回 `None`（**不是 0**：没测 ≠ 没差） |
| **单耳谱线索** | 前后/上下（中矢面）判别不靠 ILD/ITD（该平面上它们恒为零），而靠耳廓造成的**谱峰谷**；耳机改写谱形 = 改写记录里的方位线索 | 能报数值，**但不能当判据**：测的是人工耳，不是你的耳廓 |

### 文献登记（按可信度分级；没核到原文的不给数字）

| id | 结论 | 出处 | 状态 |
| --- | --- | --- | --- |
| S2 | 前后判别最关键的是 **5–6 kHz**（XGBoost 特征重要性指向 gammatone 第 30/31 通道 ≈5.5/6 kHz 的 ILD 标准差；CNN 梯度归因图亦指向 5–6 kHz） | Zieliński et al., EURASIP J. ASMP 2022:3（开放获取，已取全文） | **已核** |
| S3 | 听者**个体化**的谱线索在 **8–16 kHz** | Langendijk & Bronkhorst, JASA 112, 1583 (2002) | 已核；但本库该频段跨源离散度大 → 只标注 |
| S4 | 水平面三类线索里 **ILD 单独约 90%** > IC > ITD | 同上（实验 3） | 已核 |
| S1 | 中矢面"方向带"由中心频率决定 | Blauert, Acustica 22, 205–213 (1969/70) | 经 S2 同文转述；**带边界在原文附录表 4，本机未取到** → 不给数字 |
| S5 | 双工理论边界：>1600 Hz 走 ILD、<800 Hz 走 ITD | 二手转述 | **未取到一手**，只作方向 |
| S6 | 低频成分参与中矢面定位 | Morimoto et al., Acoust. Sci. & Tech. 24(2), 76–82 (2003) | 文献存在且主题吻合，**结论未取到** → 不用其数字 |
| S7 | 100–1600 Hz 不规则性影响前后判别 | 项目原记为 ICA 研究 | **本轮检索未命中，未取到原文** → 登记存照，**不作任何判据** |

**本模块因此没有任何"空间可闻阈"**。空间感知的阈值与"音色偏差 6 dB"不是一回事，
文献没给到可核对的数字时，只报量级。

## 4.38 测量噪声基线（`src/repeatability.py`）——文献没有的判据，从数据里自造

`spatial.py` 如实登记了"空间可闻阈没有可引文献"。但有一条判据**不需要文献**：

> 同一个型号被不同人工耳/来源测多次（本库 185 型号有 ≥2 源），
> 曲线之间的差异 = 测量链路的**可复现性上限**。
> 偏差小于这个上限的，量到的多半是测量架，不是耳机。

ISO 5725（重复性与再现性）/ Gage R&R 的思路：**先量仪器的噪声，再谈被测对象的差异**。
它不回答"能不能听出来"，它回答"**这个差异值不值得讨论**"——两层判据各管各的。

全库实测（`python src/repeatability.py`，232 个多源型号）：

| 频段 | 跨来源极差中位 | 跨来源 σ 中位 |
| --- | --- | --- |
| 5–6 kHz（前后判别关键区） | **2.81 dB** | 1.30 dB |
| 8–16 kHz（个体化线索区） | 2.84 dB | 1.35 dB |
| 20–800 Hz（ITD 主导区） | 1.00 dB | 0.48 dB |
| 100–1600 Hz | **0.51 dB** | 0.24 dB |

**这组数字本身就是结论**：

1. 高频段（5–16 kHz）的测量噪声是低频段的 **5.6 倍**——§5 第 4 条
   "口径未完全对齐"这个已知局限，第一次有了**定量刻画**；
2. 100–1600 Hz 恰好是**全频段里测得最稳的**（0.51 dB）——如果那条 ICA 结论
   真的落在这个频段，它反而是最可信的测量区间（这条推理待文献，不作为结论）；
3. 用 2.81 dB 基线判 5–6 kHz：**743 款超出测量噪声**（差异值得讨论），
   **705 款在噪声以内**（先怀疑测量架再怀疑耳机）；极端型号达 5.5–7.5× 基线。

测试 `tests/test_repeatability.py`（10 用例）钉住四条纪律：
单源型号不参与基线、同源完全一致则基线为 0、**小于基线的偏差不得判为超出**、
样本不足（<3 个多源型号）返回 None 而不是 0。

## 4.4 输出自带效力边界（不武断）

引擎**每次输出都先打印一段免责声明 + bootstrap 分档**，不是可选项：

```
这是**推荐候选集**，不是测量结论，更不是"排名"。
这个分数只衡量一件事：实测频响曲线与某条目标曲线的加权 RMS 偏差。
它**不能**告诉你：声场、结像、瞬态、大音量失真、单元一致性、佩戴、
隔音、做工、驱动难度、保值率……
```

表头写 `候选（非排名）` 而不写 `排名`——ordinal 编号会让人以为可以按序下单。
分档按 CI 重叠切，实测默认参数下**前 10 名全部落进同一档**，
于是"第 1 名"这个说法在统计上不成立。

`--no-tiers` 可关掉分档（只影响速度）。`tests/test_epistemics.py` 钉住这些措辞，
防止以后有人把表头改回光秃秃的"排名"。

**为什么这么做**：`stats.py` 早就测出前 14 名 CI 全部重叠。知道这件事却不告诉
使用者，等于纵容误读——这是本项目唯一一条"关于怎么说"的硬约束。

## 4.5 音乐层 `src/music_trend.py` + `src/music_match.py`

回答「**我这些曲库适合什么耳机**」——把"听什么"变成可复算的输入，而不是靠形容词。

**测量**（`music_trend.py`）：按目录抽样（跨子目录铺开取中位曲）→ 全采样率 Welch PSD → 7 段线性功率占比 + 100Hz–10kHz 倾斜。
- **为什么不复用 `music_profile.py`**：它把文件解码成 22.05kHz，奈奎斯特只有 11kHz，`6–16k` 与 `16–20k` 两段**必然测错**（恒为空）。必须全采样率。
- 口径与 trackscore.ai 已发布档案一致，可外部对照。
- `--replot` 用已存 JSON 重绘，不必重新解码。

**匹配**（`music_match.py`）：音乐测量同时决定两件事——
1. **权重**（哪里重要）：能量集中的频段权重更高（经 `alpha=0.5` 压缩 + `floor` 抬底；不平滑会把权重全喂给低频）。
2. **目标方向**（要不要补）：低频目标**扫 −4/−2/0/+2 dB 四档**，而不是选一个数字当真理——「该抵消多少」取决于听音音量与偏好，**测量推不出来**。
3. 聚合用 **Borda 名次共识**（不同参数下 RMS 绝对值不可比，名次可比），并在**去掉音乐加权**的对照组上再验一遍；只有两种加权都靠前的型号才算稳健。

```bash
python src/music_trend.py                    # 测量 → data/music_trends.json + out/music/trends.png
python src/music_trend.py --replot           # 只重绘图
python src/music_match.py                    # 24 次排名 + 共识 → data/music_match.json
python src/drive_need.py                     # L2：由阻抗/灵敏度推「推到 110/120dB 需多少 mW/V/mA」
python src/engine.py --music-trend "BA OST"  # 单目录交互式查询
```

**主流可购白名单**（`mainstream_match.py`）：AutoEq/squig 的曲线库天然偏向发烧友与小众型号，
**不做这一步会把「有实测」误当成「买得到/认得出」**（第一版候选集就踩了这个坑：DCA、Warwick 静电、
已停产的 Oppo PM3 排在前列）。做法是显式白名单（国内渠道常见 + 讨论度高），宁少勿滥；
排名池从 849 收到 86。**这是方法论上的必修项，不是可选优化。**

**「低频有要求」不是一维**，拆成三个可测量：`sub_bass`(20–60Hz 下钻多深)、
`sub_extension`(20–40Hz 相对 60–200Hz，真延伸)、`low_mid`(200–500Hz，糊的来源)。
理想形状是 sub/sub_ext 高、bass 中高、low_mid 低——三项全拉满是闷不是弹。
（实测结论：主流池里 `sub_extension` 为正的只有 4 个，见 `out/低频需求_主流候选_*.md`。）

**驱动门槛**（`drive_need.py`）：本层唯一能"算"的部分，也是跨厂商比较最容易出错的地方——
森海标 dB/V、DCA/Focal 标 dB/mW，**不换算就并排比会得出相反结论**。统一公式 `dB/V = dB/mW − 10·log₁₀(Z) + 30`。
低阻平板的瓶颈常是**电流**而非电压（实测：DCA EXPANSE 需 98.7mA、E3 需 60.9mA），很多 dongle 标称"能推 300Ω"说的是电压能力。

## 4.11 积分域：Bark 临界频带（`src/perceptual.py`）——修掉一个数学缺陷

引擎原来在 121 点 1/12 倍频程网格上求 `Σ w·d²`。网格按恒定比例（5.9%）分布，
而**人耳的频率分辨率是按临界频带走的**（Bark < 500Hz ≈ 100Hz 恒定，> 500Hz ≈ 0.2·f）。

**实测缺陷有多大**（`python src/perceptual.py`）：

| 频率 | 1/12 倍频带宽 | Bark 带宽 | 倍程/Bark |
|---|---|---|---|
| 50 Hz | 3.0 Hz | 76.9 Hz | **25.9×** |
| 100 Hz | 5.9 Hz | 80.8 Hz | 13.6× |
| 1 kHz | 59.5 Hz | 166.7 Hz | 2.8× |
| 8 kHz | 475.7 Hz | 1887.8 Hz | 4.0× |

→ 50 Hz 处同样的 dB 误差，在旧度量里对 RMS 的贡献是 1 kHz 处的 **26 倍**。
感知权重部分补偿了这一点，但"权重"（哪里更敏感）和"积分域"（哪里该按什么带宽积分）
**是两件事**，用一个参数干两件事，调参必然互相牵扯。

**修法**：先按 Bark 带求组内均值，再对带求 RMS。RMS 项与峰护栏项用**同一个**积分域
（否则等于把两套口径混进一个分数）。

**影响（min_sources=2，Harman 基准）**：

| | 第 1 名 | 分数 |
|---|---|---|
| 1/12 倍频程（旧） | Oppo PM3 | 84.7 |
| Bark 临界频带（新） | Sennheiser HD 560S | 91.1 |

排名整体重排、分数上移（带内均值降低了方差）。更重要的：**Bark 积分下 #1 第一次
可区分**（EXPANSE 独占一档，CI 85.6–91.2，其余上限 90.0）——降噪之后真实差异才显出来。

切换：`python src/engine.py --bark`（默认仍是旧行为，便于对照）。

### 撤掉了响度换算，理由记在这里

本模块原打算同时实现 ISO 532-1（Zwicker）响度，把 dB 偏差换成 sone/phon。
**做不出来，已删除**：

    1kHz / 40 dB SPL 纯音 → 公式给出 31.1 phon（ISO 226 定义应为 40 phon）
    1kHz / 60 → 70 dB     → 响度比 6.51×（Stevens 定律期望约 4×）

第二条说明**不是纯尺度误差**——反解出指数项应约 0.16 而非 0.25，即对 `alpha` 或
`L_TQ` 的理解有误。能核到 ISO 532-1 原文系数表之前，宁可不提供，也不给差 9 phon 的数字。
按"能算的绝不猜"：**Bark 标度与积分可验证，响度常数不可验证，后者不做。**

## 4.10 候选集的统计严谨性（`src/stats.py`）—— 本项最重要的发现

引擎此前输出「87.3 vs 86.6」却不说明这个差是否可信，**那是伪精度**。

### 做法：频率维 bootstrap
把 121 个频点当样本、有放回重采样，按同一公式重算得分，重复 300 次 → 分的 95% CI。
CI **只**覆盖频谱形状的测量不确定性；**不含**单元个体差异、人工耳传递函数差异、
批次/耳垫差异（那些需要多只样本的数据，本项目没有）。这一点在输出里如实标注。

### 实测结论（Harman 基准、delta 全 0、min_sources=2）

| # | 型号 | 得分 | 95% CI | SE |
|---|---|---|---|---|
| 1 | Dan Clark Audio EXPANSE | 88.38 | 85.78 – 91.13 | 1.44 |
| 2 | Oppo PM3 | 84.74 | 81.78 – 87.10 | 1.29 |
| 3 | Austrian Audio Hi-X60 | 84.55 | 82.30 – 87.38 | 1.36 |
| 4 | Focal Hadenys | 83.68 | 79.50 – 88.87 | 2.51 |
| 5 | Bowers & Wilkins P7 | 83.64 | 79.08 – 88.04 | 2.27 |
| … | … | … | … | … |

**前 14 名全部落在同一档（CI 跨度 76.8–91.1）。相邻名次 13 处 CI 全部重叠，
连 #1 与 #2 都不可区分。** 分差 0.05–3.6 分，而 SE 是 1.0–3.7 分。

### 这对结论意味着什么（纠正性的）

1. **按排行榜下单等于按噪声下单。** 分差 < ~5 分的名次差异不可解读。
2. 本项目此前若干"推荐第一名"的表述**过度解读了噪声**，此处更正。
3. **可区分的信息在具体轴上，不在聚合分里**：`sub_extension`（主流池只有 4 款为正）、
   `low_mid`（糊的来源）、驱动门槛、价格——这些轴的差异远大于 SE，
   所以 Focal Azurys 的推荐依据始终是「sub_ext +1.9 是主流池唯一显著正值」，
   而不是聚合分排名。这条结论不受本轮影响。
4. 方法论里"前两名分差 < 6 要求一起试听"的规则**应该升级为**：
   输出**档**而不是排名，同档内必须靠具体轴 + 试听决定。

### 复算
```bash
python src/stats.py --top 14 --boot 300      # 带 CI 的排名 + 分档
```

## 4.9 感知权重：ISO 226 等响曲线（`src/psycho.py` + `src/weight_sensitivity.py`）

`base_weight()` 现在是 **ISO 226:2003 等响曲线 + floor**，不再是手调常数。

**系数表与公式**（可引用的一手来源，见 `src/psycho.py` docstring）：

    A_f = 4.47e-3 · (10^(0.025·L_N) − 1.15) + (0.4 · 10^((T_f + L_u)/10 − 9))^α_f
    L_F = (10/α_f) · log10(A_f) − L_u + 94

自校验（`tests/test_psycho.py`，12 个用例）：
- **恒等式**：f = 1000 Hz 时必须给出 L_F = L_N（"方"的定义）——全 phon 档验证，
  同时验证公式形式与四张系数表没抄错；
- 绝对值：40 方 @ 20Hz≈99.9 / 100Hz≈64.4 / 4kHz≈36.7 / 10kHz≈54.3 dB，
  80 方 @ 10kHz≈92 dB，听阈 @ 4kHz≈−8.5 dB，均与公布值吻合。

### 关键发现：floor 才是关键参数，不是 phon 档

**为什么不能直接用等响敏感度当权重**——实测（`src/weight_sensitivity.py`）：

| 权重方案 | Spearman | 前 10 重叠 |
| --- | --- | --- |
| 历史手调权重 | 1.000 | 10 |
| **ISO 226 floor=0.30（现默认）** | **0.967** | **7** |
| ISO 226 floor=0.15 | 0.951 | 5 |
| 全平坦 w=1 | 0.945 | 8 |
| ISO 226 floor=0.05（纯敏感度） | 0.918 | **4** |
| ISO 226 40 方 | 0.841 | 2 |

floor=0.05（纯敏感度）会把**游戏耳麦 Sennheiser PC38X 顶到第一名**——
因为 20 Hz 与 >10 kHz 的权重被压到接近 0，"只有中频好"的耳机于是占便宜。

根因：**纯音敏感度 ≠ 宽带谱差的显著性**。等响曲线说 20 Hz 在 80 方时敏感度
仅 ~1e-4，直接当权重等于完全忽略超低频；但音乐少了超低频你**听得出来**（声音变薄）。
floor 就是"谱差在任何频段都可闻"的下限。

floor=0.30 的取值依据：与历史手调权重的形状最接近（前 10 重合 7/10），
而手调值是多年听音验证过的、不是拍的。**改这个值前先跑
`python src/weight_sensitivity.py` 看排名稳定性。**

顺带：闭式解在其范围下端（phon→0 时 `10^(0.025·L_N) − 1.15` 变负）精度下降，
实测 phon=0 时偏差 0.01 dB。这是 ISO 226 闭式解的已知局限，测试容差已按 0.05 dB 设。

## 5. 已知局限（诚实清单）
1. **没有价格/规格**：AutoEq 只有曲线 → 本项目是"音色层"，预算/驱动/佩戴仍需外部数据（旧技能 `market_catalog.json`）。
2. **参考基线 ≠ 中性目标**：数据集中位数反映的是"人群平均形状"（含大量消费级），不等于 Harman/DF 目标。
3. **锚点少 = 易过拟合**：只给 1–2 个锚点时，模型退化成"找更像它的"，外推能力弱；要外推需配 delta。
4. **口径未完全对齐**：oratory1990 / Rtings / Innerfidelity 的人工耳不同，跨来源一致性只能当**相对**参考。
5. **单条 FR 推不出**：声场 / 隔音 / 佩戴 / 失真——需 L-AUX（单元·腔体）或其它测量。
6. **阈值（`tilt` 权重、`peak-guard`、扣分系数）未校准**——仍是启发式，改动前先跑 `tests/`。
7. **音乐层只覆盖频响维度**：声场/结像/瞬态/大音量失真/佩戴/隔音，本层一律说不出。曲库画像能推出的是"哪段该准确、哪段别叠加"，推不出"哪只更好听"。
8. **音乐加权会把权重压在低频**：本库 20–250Hz 占 49–70% 能量，加权后低频权重大约是高频段的 5 倍 → 排序被低频准确性主导，**2–6kHz 人声区的相对权重被低估**。这是为什么必须同时看"不加权重"的对照组。
9. **目录平均值混合不同母带**：同一目录里可能同时有 320K MP3、cue+wav、96kHz FLAC（BA OST 即是），"目录画像"是混合产物。
10. **"用耳机补音乐"本身有争议**：本层的默认立场是忠实地重放，因此倾向于不叠加；主张"搭配（加亮度）"的路线在 2–6kHz 上会得出不同结论。分歧已写进输出报告，未替用户取舍。
